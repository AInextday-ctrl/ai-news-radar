微软披露ARTEX框架助推自动化攻击

✍️ 记者 / 供稿: Maximilian Schreiner

微软安全情报分析显示，开源AI渗透测试框架ARTEX正被多国背景的网络攻击组织利用，实现从侦察到数据窃取的全流程自动化

⚡ 核心要点提炼与关键事实

  • 【核心事件】微软安全情报团队与多个具备国家背景的攻击组织在全球网络安全环境：深度分析ARTEX如何利用AI智能体实现自动化渗透与数据窃取
  • 【起因与机理】该框架虽初衷为渗透测试，但被恶意主体利用以实现机器速度的攻击部署
  • 【核心事实细节】ARTEX利用多智能体实现攻击路径自动化。
  • 【各方立场与态度】攻击行为具备低人工介入、高响应速度特征。

📰 深度报道原文实录

THE DECODER 权威实录

人工智能框架 ARTEX 可自动执行从侦察到数据盗窃的网络攻击。微软的一项分析显示了国家支持的组织和网络犯罪分子如何以机器速度使用其专门代理，以及防御者如何应对。

自 2026 年 7 月发布以来，人工智能驱动的渗透测试框架 ARTEX 已成为网络攻击的首选工具。该软件最近被怀疑用于入侵 CIA、NGA 和 ODNI 运行的分析系统（Link nicht geprüft）。在美国金融犯罪机构 FinCEN 报告安全事件之前不久，该漏洞就出现了。联邦调查局和美国农业部早些时候报告了这一事件。

微软威胁情报的一份报告现在详细介绍了 ARTEX 的工作原理及其传播范围。 GitHub 用户“Autumn-27”于 7 月发布了源代码，并于 10 月将其删除，但其他开发者仍在分发副本。中国安全公司 ThreatBook 还销售商业 Pro 版本。微软表示，来自中国和朝鲜的国家支持组织已将 ARTEX 整合到其运营中，包括 Salt Typhoon、Crystal Typhoon、Onyx Sleet 和 Storm-0940。该公司表示，出于经济动机的网络犯罪分子也使用该系统，国家支持的犯罪集团和犯罪集团都在供应链攻击等行动中部署该系统。

专门的人工智能代理以最少的监督运行现有的安全工具

微软指出 ARTEX 并未发明新的攻击技术。相反，该框架几乎无需人工干预即可运行现有的安全软件，包括 Nmap、Sqlmap、Metasploit 和自动无头浏览器等工具。攻击者可以连接任何大型语言模型，包括没有安全护栏的修改版本。内置池功能会根据错误或使用限制自动切换模型或 API 密钥，从而使任何单个 AI 提供商都难以跟踪攻击。

据微软称，该系统建立在多代理架构之上。目标模型将攻击者的指令分解为可验证的子目标。从那里，规划代理不断审查知识图（已发现的系统和漏洞的动态图），以分配短期攻击任务。工作代理通过系统命令执行这些任务，包括在 Web 服务器上部署 Web shell、读取密码文件或劫持云帐户。每个新发现都会反馈到地图中，并提示规划代理进行下一步，直到报告代理记录所有被利用的缺陷。

机器速度攻击促使微软推荐主动欺骗

该公司发现，自动化将防御者的响应时间缩短至几分钟。在一个案例中，AI 代理只需五分钟即可在 GitHub 上搜索意外泄露的凭据，并从云密钥存储 Azure Key Vault 中提取数据。在 Storm-0940 活动期间，该公司记录了超过 151,000 次来自自动密码猜测的失败登录尝试，峰值为每分钟 2,900 次。在同一活动中，微软观察到一些受感染的应用程序授予自己最高管理员权限。

传统的基于规则的过滤器经常无法抵御 ARTEX，因为它们依赖于已知 IP 地址或浏览器标识符“artex-enrich”和“norma”等固定标记。代理及其人工操作员不断更改这些标记，并通过旋转 VPN、代理服务器或 Tor 重新路由被阻止的流量。即使安全团队发现并隔离了漏洞，这通常还不够。由于 ARTEX 通常同时运行两到三个攻击链，因此其代理会立即适应并以机器速度转移到新的网络路径。

ARTEX 仍然会暴露出巨大的流量，因为该框架默认情况下不会隐藏其活动。 Microsoft 建议采用针对 AI 代理操作方式量身定制的欺骗技术，以及严格的访问控制、速率限制和针对受感染设备的自动实时隔离。

蜜罐为自主代理提供了有吸引力但毫无价值的诱饵系统，以将流量从真正的目标上拉走。人工延迟循环（称为 tarpit）会减慢请求速度并耗尽代理的内置时间和计算预算。微软表示，假胜利特别有效，因为 ARTEX 的目标模型寻找可验证的违规证据。当陷阱返回令人信服的虚假成功消息时，人工智能会认为其任务已完成并自行停止攻击。

当代理试图劫持其他人的人工智能计算时，诱饵凭证（称为蜜币）会触发早期警报。微软自己的测试表明，这些欺骗策略大大减少了针对真实系统的成功攻击流量，并提供高精度数据来识别背后的攻击者。

这些防御措施能持续多久仍取决于微软的分析。建议的防护措施在很大程度上取决于 ARTEX 是否保持噪音和未被屏蔽。一旦攻击者分散其请求，阈值过滤器和诱饵可能会达到其极限。正如最近的安全测试中所见，独立识别人工测试环境和欺骗企图的强大语言模型也带来了类似的风险。

ARTEX的广泛应用标志着网络攻击已进入“智能体即服务（AaaS）”阶段。传统基于特征码的防御体系在动态自演进的AI攻击流面前几近失效，未来安全防御重心将彻底从“静态防护”转向“智能体行为审计”与“算力行为异常检测”。
