Optimizely供应链被攻陷，百余家大型机构面临安全威胁

✍️ 记者 / 供稿: Report URI Blog

2026年11月16日，Optimizely平台被植入恶意JavaScript代码，导致包括Zoom、BBC及汇丰银行在内的178家机构网站受感染

⚡ 核心要点提炼与关键事实

  • 【核心事件】Optimizely（Web实验平台供应商）；受影响机构包括Zoom、CNN、汇丰银行、Salesforce、GitLab等：攻击者通过Optimizely控制面板篡改Project JavaScript，导致下游网站加载恶意脚本，引发资产窃取与iOS漏洞攻击
  • 【起因与机理】第三方依赖项的信任机制被利用，绕过了单一企业网站自身的安全基础设施防护
  • 【关键技术规格】Optimizely平台被非法篡改，恶意JS代码通过合法CDN分发。
  • 【各方立场与态度】第三方依赖项信任机制引发的供应链安全隐患。

🤖 雷达专属 AI 研判与技术透视

此事件标志着现代Web架构中‘CDN即信任源’的范式漏洞被彻底放大，第三方脚本执行权限缺乏细粒度隔离已成为企业的系统性软肋。即使拥有完备的主站安全防护，企业若无强制执行内容安全策略（CSP）与子资源完整性（SRI）校验，仍无法阻断此类经由合法第三方基础设施转递的复杂供应链攻击。

Report URI Blog 权威实录

2026 年 11 月 16 日，恶意 JavaScript 通过 Optimizely Web 实验平台向 178 个组织的访问者提供。该列表包括一些世界上访问量最大的网站：Zoom、BBC、CNN、Salesforce、GitLab、IKEA、HSBC、Equifax、Air France-KLM、Ledger 和 Peacock。

该恶意软件是一个多用途工具包。它将加密货币钱包地址交换为攻击者的地址，浏览支付卡，窃取 cookie 和屏幕截图，并在 iPhone 和 iPad 上提供 Coruna 和 DarkSword iOS 漏洞利用套件。加密货币已经被盗，攻击者已验证交易。

这正是 Report URI 旨在检测的攻击类型。我们的平台可以识别受信任 JavaScript 的意外更改、检测正在加载的新脚本并揭示与外部目的地的可疑连接。在这种情况下，即使原始脚本是由受信任的 Optimizely 域提供的，这些信号也会暴露恶意活动。通过适当的 CSP 执行模式，组织可以更进一步，在攻击成功之前阻止其关键部分。

这里重要的教训是，受信任的 JavaScript 并不总是值得信赖的。网站可能会因第三方依赖而受到损害，而其自身的代码或基础设施却不会被破坏。

大多数恶意代码现已被删除。截至世界标准时间 21:52，我们仅在 188 个受感染片段中的 1 个中发现了该病毒，低于世界标准时间 20:56 的 169 个。如果您的网站使用 Optimizely Web，或者您今天访问了以下任何网站，请继续阅读。

Optimizely Web 的工作原理是让每个客户从 Optimizely 的 CDN 加载 JavaScript“片段”，例如 https://cdn.optimizely.com/js/6395285578973184.js。该代码片段包含 Optimizely 的代码、客户的实验和一个名为 Project JavaScript (projectJS) 的可选字段：客户在其 Optimizely 仪表板中编写的自定义代码，该仪表板在每个页面上运行。

我们不知道攻击者如何获得对如此多不相关的客户项目的写入权限：受损的 Optimizely 系统、受损的跨客户访问凭据或其他内容。这是由Optimizely 来解释的。需要明确的是，Optimizely 的 CDN 完全满足了它的要求；这不是 CDN 缓存中毒攻击。 Optimizely 自己的网站也受到了影响：www.optimizely.com 和 login.optimizely.com 的片段都携带了该代码。
