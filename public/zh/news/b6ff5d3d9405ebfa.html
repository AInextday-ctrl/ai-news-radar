OpenAI 官方动态 权威实录

开源运行时，可帮助操作员保护正在运行的 Linux 系统，无需等待补丁或重新启动

OpenAI 和 Cisco 正在推出 Shirudo，这是一个开源运行时，可帮助团队在推出补丁时保护 Linux 系统。在受控测试中，Codex 生成的防护罩阻止了针对正在运行的 Elasticsearch 服务的 Java4Shell 攻击尝试，而无需重新启动。

我们邀请整个行业的开发人员、安全研究人员和基础设施运营商来帮助进一步开发该项目。该项目汇集了 OpenAI 的前沿人工智能、安全和基础设施研究以及思科的基础设施和安全专业知识，以帮助保护人们每天依赖的系统。

测试和部署补丁仍可能需要数天或数周的时间。同时保护服务可能具有挑战性，因为漏洞利用和合法请求可能依赖于相同的 Linux 操作。完全阻止该操作可能会使服务脱机。

Shirudo（日语中的“盾牌”）旨在帮助安全团队进行这种权衡。团队可以测试称为防护罩的临时保护措施是否可以阻止暴露漏洞的行为，同时允许合法请求通过。一旦操作员批准了防护罩，就可以在服务继续运行的同时进行部署。

Shirudo 使用 eBPF，这是一种 Linux 技术，允许小程序在操作系统内的特定点运行。这使得观察可疑活动并对正在运行的系统应用有针对性的安全保护成为可能。

OpenAI 和 Cisco 正在围绕四个核心功能设计 Shirudo：

实时保护：eBPF 防护罩可以阻止易受攻击的代码路径，而无需重新启动系统。安全团队可以在实施之前监控提议的防护措施将如何影响应用程序。

以机器速度进行防御：OpenAI 和思科正在设计 Shirudo，为代理提供可编程控制来调查漏洞、开发有针对性的防护罩，并验证其针对漏洞和实际工作负载的有效性。安全团队控制部署的内容。

可信部署：Shield 在加载前经过加密签名和验证。 Linux 的 eBPF 验证程序根据其安全规则检查 eBPF 程序，而内核安全控制则限制未经授权的更改。

硬件支持的验证：Shirudo 使用可信平台模块 (TPM) 来支持加载或删除的保护的可验证记录。运营商可以使用此证据来检查系统是否满足其安全要求。

Linux Plumbers Conference 的 Shirudo 技术演练展示了如何应用防护罩并在目标主机上验证它。 Java4Shell 漏洞是另一个示例，说明了有针对性的防护如何在准备永久补丁的同时保护正在运行的应用程序。使用 OpenAI 的 Codex，该团队生成了一个盾牌，为 Java 的 Base64 解码器添加了输入检查，并将其直接附加到正在运行的 Elasticsearch 进程。当尝试利用该漏洞时，防护罩会拒绝恶意输入，从而在 Elasticsearch 继续运行的同时阻止攻击。您可以在这里阅读更多内容。

重新思考基础设施

Shirudo 是迈向能够适应新威胁并同时保持可靠性的基础设施的第一步。我们希望加强大规模部署这些保护所需的操作系统基础，包括强化内核和核心服务、限制工作负载权限以及使更新和恢复更安全。
