GitHub单月代码提交量飙升至74亿次

✍️ 记者 / 供稿: The New Stack
📖 阅读原资讯官网报道 ↗
GitHub月度代码提交量暴涨，基础设施面临巨大压力，年内紧急扩容400万CPU核心及160PB存储以应对AI代理带来的流量增长

⚡ 核心要点提炼与关键事实

  • 【核心事件】GitHub在GitHub Universe 年度大会：单月提交量激增至74亿次，紧急追加400万CPU核心与160PB存储
  • 【起因与机理】AI代理任务产生的自动化请求爆发式增长导致基础设施压力剧增
  • 【关键数据与实测】月提交量达74亿次，基础设施大规模扩容。
  • 【各方立场与态度】AI自动化任务成为系统负荷主因。

🤖 雷达专属 AI 研判与技术透视

AI不仅在写代码，还在忙着把服务器写宕机。当代码库被AI代理变成工业流水线，GitHub现在的扩容速度，约等于在高速公路上边开车边换发动机。

GitHub 看到了前所未有的需求，并正在更新其核心基础设施以跟上步伐。

8 月份，GitHub 表示每月提交量为 29 亿次，高于 4 月份的 14 亿次。在周三的 GitHub Universe 会议上，该公司宣布现在每月有 74 亿次提交。从这个角度来看，开发者到 2024 年每月向该平台提交了 6500 万次承诺。

这种增长是一个很大的问题，但该公司的停电已经成为一个反复出现的主题。正如该公司所说，原因是使用量快速增长，这主要是由“代理需求”推动的。

8 月，GitHub 首席技术官 Vlad Fedorov 宣布该平台增加了 300 万个 CPU 核心（主要在 Azure 上）以支持这一增长。现在，GitHub 表示，今年到目前为止，它已经为 GitHub Actions 增加了 400 万个 CPU 核心、160 PB 高速存储和更多计算能力

该公司还增加了 50 Tb/s 的网络容量，以保持所有这些数据的流动。

GitHub 还利用这一公告重申其重新构建平台以分离计算和存储的承诺。它在本月早些时候首次谈到了这一点。当时，该公司指出，其内部基准测试表明，这种新架构可以提供高达 35 倍的写入吞吐量。

“代理正在改变软件开发的数量和形式。增加容量很重要，但仅靠容量并不能帮助我们实现这一目标。我们还必须改变架构，”微软核心人工智能执行副总裁 Jay Parikh 在公告中写道。

在 2026 年，计算和存储的分离并不完全是激进的做法，但它表明 GitHub 正在尝试在遗留基础上进行扩展。迁移到 Azure 及其服务本质上是唯一的选择，尤其是在公司自己的数据中心容量不足的情况下。
