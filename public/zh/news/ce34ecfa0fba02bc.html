AI供应链隐私审计：200万次蜜罐测试揭露数据泄露

✍️ 记者 / 供稿: Dan Goodin

安全研究员HD Moore通过200万次蜜罐测试发现，AI路由与中介服务存在严重的数据隐私泄露漏洞

⚡ 核心要点提炼与关键事实

  • 【核心事件】HD Moore（Dragos首席研究官）在AI服务路由与中介平台：植入200万个可追踪的伪造敏感凭证进行安全审计，发现严重数据泄露与隐私违规
  • 【起因与机理】验证当前复杂的AI供应链对敏感信息处理的合规性与安全性
  • 【关键数据与实测】利用200万个蜜罐凭证实现供应链审计。
  • 【各方立场与态度】零数据留存政策（ZDR）在执行端全面失效。

📰 深度报道原文实录

Ars Technica 权威实录

研究人员在通过庞大的人工智能服务网络发送的请求中植入了 200 万条数字绊线，以查明委托给他们的敏感信息发生了什么。他们发现的是一个像筛子一样泄露高度敏感数据的生态系统。

这次泄露是通过一项巧妙的实验发现的，该实验旨在测试敏感信息是否会通过广泛使用的人工智能服务的庞大链条泄露，以及当泄露时这些信息如何被利用。当今的许多人工智能应用程序都使用 OpenRouter 或 Vercel 等充当代理的服务。这些“人工智能路由器”有时也称为“人工智能网关”，接收人工智能应用程序最终用户发送的大量提示，并根据收费最低或最适合给定任务等标准将它们路由到可用的推理引擎。开发人员没有使用 Anthropic、OpenAI 或其他大型提供商，而是雇佣了 AI 路由器来寻找最合适的模型。

安全漏洞、盗窃和侵犯隐私

为了测试潜在的泄漏，研究人员 HD Moore 收集了一系列 AWS 访问密钥、与空 AWS 帐户相关的功能凭证、SSH 等服务的密码以及唯一的 URL、DNS 名称和私有 git 存储库引用。这些秘密以前都没有被使用过，他控制着使用这些凭据接收任何请求的基础设施。然后，他将每个秘密植入到发送给单个提供商的一个提示中。如果任何秘密被泄露，这些“金丝雀”（之所以如此称呼，是因为它们类似于那只鸟被带入煤矿时的角色）将使摩尔能够识别链条中负责的每个环节。

研究结果令人震惊。其中包括：

有证据表明，至少三个人工智能提供商受到攻击者的危害，攻击者利用他们的访问权限来获取他们收到的虹吸提示

推理市场中的多个经销商记录了提示并以某种方式将它们传递给使用凭据的人

多个人工智能提供商未遵循嵌入到指定术语（例如零数据保留（ZDR）或“不收集数据”）的标志中的最终用户隐私设置的案例

安全公司 Dragos 首席研究官摩尔周四写道：“我们向人工智能提供商发送了近 200 万条包含独特、可追踪秘密的人工智能提示，然后观察这些秘密出现的位置。” “我们的发现揭示了安全漏洞、迅速盗窃以及保护客户数据的普遍失败。”

尽管提示在传输过程中被加密，但它们在大型推理经销商网络内的每一跳都会被解密。该提示首先被发送到人工智能路由器，该路由器读取其中的明文以确定最合适的推理提供者来处理该请求。通常，提示会被发送到可用模型池，这些模型有时在不同的托管提供商内运行。提示还可以从一台 AI 路由器（例如 Vercel）传递到另一台 AI 路由器（例如 OpenRouter）。这些玩家中的每一位都可能会记录提示并将其存储到其策略要求的时间（如果不是无限期的话）。

人工智能时代的狂野西部

最令人担忧的调查结果是三个独立托管提供商的违规行为。危害其中一个提供商的攻击者重复使用了“数百个”AWS 密钥。摩尔写道：

每个密钥都是在 10 月下旬的几个短窗口内通过一次请求发送给一个提供商，而我们在这些窗口期间发送的每个请求都被盗了。一些被盗的密钥来自提供者在模型运行之前拒绝的请求，这告诉我们攻击者是在提供者的前门复制请求，而不是在推理堆栈更深的地方复制请求。在另外两次泄露中，一些被盗的请求被标记为 ZDR。当攻击者已经在里面时，隐私标志没有任何帮助。

与这三个提供商的黑客攻击相关的各方随后测试了每个密钥（在某些情况下在播种后数小时内），以查看它可以访问哪些资源。各方查看 S3 存储桶、秘密管理器和参数存储，以寻找更多凭证。他们还尝试在 AWS Bedrock 中启用托管模型，并添加自己的 IAM 用户来维护访问权限。总之，被盗的诱饵密钥在 AWS API 调用中被使用了“数万次”。

🤖 雷达专属 AI 研判与技术透视

AI应用通过路由中介连接多层供应商的碎片化生态，已成为企业数据合规的“黑盒”灾难点。当前的供应链缺乏端到端的信任保障，中介平台的无差别日志记录与零数据留存政策的执行失效，表明现行法律监管与商业承诺在复杂的调用链面前显得极其脆弱。
