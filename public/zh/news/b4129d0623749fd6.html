OpenAI发布GPT-6.2模型提示词优化指南

✍️ 记者 / 供稿: Jonathan Kemper

OpenAI发布针对Astra与Sol模型的提示词模版，旨在解决回复过于简略及过度询问的问题，并更新API以支持舍弃推理过程数据

⚡ 核心要点提炼与关键事实

  • 【核心事件】OpenAI在开发者文档及模型API接口：发布提示词模版及API更新，旨在优化模型回复风格、主动性及输出质量
  • 【起因与机理】解决模型在复杂任务中回复冗余、过度依赖推理过程记录及交互逻辑滞后的问题
  • 【关键技术规格】针对Astra（高性能）与Sol（高性价比）模型发布标准化提示词模版。
  • 【各方立场与态度】调整模型行为预期，要求在具备授权前提下主动采取行动而非被动询问确认。

📰 深度报道原文实录

THE DECODER 权威实录

OpenAI 发布了适用于 GPT-6.2 Astra 和 Sol 的新提示模板，涵盖写作风格、主动性和编码，以及可能丢弃推理内容的 API 更改。

OpenAI 表示，转向 GPT-6.2 Astra 或 Sol 的开发人员应该检查他们的系统提示。该公司在模型文档中发布了复制准备提示，以遏制在两个版本中观察到的行为。 Astra 专为最苛刻的任务而设计，而 Sol 则可以以较低的成本处理复杂的工作。

默认简洁性改变了开发人员提示写作的方式

据 OpenAI 称，Astra 默认情况下比早期模型的书写更加简短和直接。这意味着切换的开发人员应该重新考虑诸如“简洁”之类的指令。为了在日常工作中作为同事使用，该公司建议采用用户和源术语、使用主动语态并将要点放在首位的提示。当为外部读者写作时，模型应该考虑到他们缺乏上下文。编辑时，应保留作者的意思和措辞。

在长任务中，模型有时会将其推理或其他代理消息的速记带入最终响应。一个专门的提示告诉它写下最终答案，这样它就可以独立存在。

将您的最终答案视为用户第一次查看您的作品，而不是中间评论的延续。最终答案必须始终是完全独立的：用户永远不需要阅读早期的评论更新以了解上下文，因为当最终答案向用户显示时，它们会折叠起来。为目标读者重新写下最终答案和所有其他面向人的材料。不要复制或严密地解释你的推理或采用其写作风格。不要将推理、工具调用或指令中的工作速记、行话或缩写转移到子代理和自动化中。

为目标读者重新写下最终答案和所有其他面向人的材料。不要复制或严密地解释你的推理或采用其写作风格。不要将推理、工具调用或指令中的工作速记、行话或缩写转移到子代理和自动化中。

GPT-6.2 应该根据假设采取行动，而不是等待许可

OpenAI 表示，当用户意图不清楚时，GPT-6.2 有时会建议下一步并等待确认。该公司建议，只要模型获得授权，就会出现提示，告诉模型自行执行这些步骤。它应该仅在任务范围发生重大变化、真正的阻碍、用户必须做出的决定或不可逆转或破坏性的操作时暂停。

当细节不清楚时，模型应该做出可逆的假设，标记它们，然后继续工作。 OpenAI 补充道，更高的推理能力还有助于它在长时间任务中完成最终检查。

避免在任务未完成时停止结束回合，或者如果您可以采取授权的下一步，而是在任务范围内采取后续步骤来处理用户的请求。如果您在结束回合之前的最终响应是建议的下一步、计划、要求用户进行例行决策的请求、要执行的任务的说明或向用户的类似移交，请自行采取这些步骤，以朝着用户要求的方向取得进展。确保您有权这样做，并向用户标记您所做的任何假设或决定。仅当任务范围发生重大变化、您被具体阻止、有用户需要解决的决定或在不可逆转或破坏性操作之前才停下来向用户澄清。

仅当任务范围发生重大变化、您被具体阻止、有用户需要解决的决定或在不可逆转或破坏性操作之前才停下来向用户澄清。

更精简的代码输出意味着默认情况下更少的测试和更少的抽象

OpenAI 表示 GPT-6.2 编写的代码比其前身更高效。其模板指示模型重用现有逻辑并避免不必要的辅助函数，同时仅在请求、存储库要求或需要捕获特定回归时添加新测试。更少的行数和更短的变量名并不能代替简单性。

🤖 雷达专属 AI 研判与技术透视

模型向更高效的推理及任务自动执行演进时，如何通过Prompt约束强制模型脱离‘推理链式思考（CoT）’惯性是当前应用层优化的关键。此举反映了OpenAI试图解决大模型作为Agent时因过度谨慎导致的‘交互磨损’，通过系统级设定将模型输出与思维链路彻底解耦，是提升复杂业务流自动化效率的必然路径。
