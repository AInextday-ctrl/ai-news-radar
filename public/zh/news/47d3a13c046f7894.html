数百个网站向毫无戒心的访问者提供强大的恶意软件混合物

✍️ 记者 / 供稿: Dan Goodin

数字优化平台Optimizely的CDN基础设施遭恶意代码篡改，致使CNN、Zoom等178家机构网站向访客推送加密货币盗窃及iOS漏洞利用程序

⚡ 核心要点提炼与关键事实

  • 【核心事件】Optimizely（数字优化平台）：植入并分发恶意track.js脚本以窃取数据及推送iOS漏洞工具
  • 【起因与机理】攻击者获取了Optimizely跨客户项目的写入权限
  • 【关键数据与实测】网站优化平台Optimizely的基础设施被植入恶意JavaScript脚本，该脚本经由合法CDN分发至包括CNN、Zoom、BBC及Salesforce在内的178个客户站点。
  • 【行业影响与走向】受影响范围涉及全球百余家高权重站点，供应链防御机制存在严重合规缺口。

📰 深度报道原文实录

Ars Technica 权威实录

研究人员周二表示，数百个使用Optimizely网站个性化平台的网站向毫无防备的访问者提供了强大的恶意软件鸡尾酒，这些恶意软件以加密货币钱包为目标，窃取支付卡数据、cookie和截图，并提供了感染iphone和ipad的漏洞利用工具包。

reportturi表示，它确定了178个网站受到影响，包括CNN、Zoom、BBC和salesforce。经过Optimizely数字签名，然后加载到客户页面的JavaScript被修改为包含恶意组件，试图感染具有多个有效载荷的访问者设备。当软件安装成功后，他们将用户加密货币钱包地址交换给攻击者。其他组件则会刷掉支付卡，窃取cookie和截图，并在iphone和ipad上发布名为Coruna和DarkSword的iOS漏洞利用工具包。

优化基础设施提供多用途恶意软件

Optimizely 提供 JavaScript“片段”，其中包括公司代码和每个客户提供的代码。 JavaScript 可以直接从 Optimizely 或客户端点提供服务，在客户服务的每个页面上运行。攻击者以某种方式将自己的代码写入每个受影响客户的 JavaScript 的一部分，然后从 cdn.optimizely.com 传递它。该域的有效证书签署了 JavaScript。

ReportURI 研究员 Scott Helme 表示，这种传送机制并不是 CDN 缓存中毒攻击，即使用 HTTP 导致 CDN 缓存有害响应。相反，攻击依赖 Optimizely 的合法基础设施（包括其域）来为受污染的代码提供服务。 Optimizely 自己的 www.optimizely.com 和 login.optimizely.com URL 的客户 JavaScript 也受到了影响。

ReportURI Helme 写道：“我们不知道攻击者如何获得对如此多不相关的客户项目的写入权限：受损的 Optimizely 系统、受损的跨客户访问凭证或其他内容。” “这个需要Optimizely来解释。”

Optimizely 代表没有回复通过电子邮件发送的问题。

这些脚本被命名为 track.js，所有四个组件同时激活。收到恶意代码的设备的响应有所不同，具体取决于其平台以及它们在传递恶意代码的最终页面上所做的操作。执行的行动包括：

1. 加密钱包地址交换。该脚本搜索九种不同加密货币的钱包地址，找到后将其替换为攻击者的其中一种。 ReportURI 表示，一些设备运行该代码的人的资金已经被盗。

2、盗卡。该脚本监视支付卡号、到期日期和 CVV 的 HTTP 请求。当这三个都存在时，会将它们发送到 https://1688360.cc/card.php。在 Stripe 和 Adyen 等托管支付 iframe 中输入的卡不受影响。

3. Cookie 和屏幕截图盗窃。当脚本交换钱包或付款措辞旁边的地址时，它会将 document.cookie、所替换的原始地址以及页面的屏幕截图发送到 https://1688360.cc/hit.php。

4. iOS 的 DarkSword 和 Coruna 漏洞利用套件。这些套件通过 5vobauua3ojpklx.icu 和 eil786npto9u5bq.icu 提供的名为 boot.js 的文件提供。该文件提供了一个隐藏的 iframe，其中包含针对所使用的 iOS 版本定制的漏洞利用链。 Coruna 可以感染 iOS 版本 13 至 17。DarkSword 可以感染版本 18.x。用于 iOS 26 指纹设备的单独链，但似乎没有做任何其他事情。本月早些时候，研究人员发现黑客可能与克里姆林宫有联系，试图通过多种途径传播 DarkSword，其中包括受损的网络分析服务。

ReportURI 发现的提供恶意脚本的网站列表有 178 个，并且如上所述，其中包括许多知名网站。目前尚不清楚该清单是否详尽。 Helme 在接受采访时表示，“据我们所知，Ars 并未受到影响，而且我也没有看到任何其他迹象。”网站管理员可以检查 ReportURI 帖子和安全公司 Cynet 发布的这篇帖子，了解是否存在泄露迹象。

目前，还没有关于漏洞利用链在安装有效负载方面有多成功的信息。除了上面的基本细节之外，还无法获得有关哪些版本的 iOS 容易受到影响的更准确的信息。此类差距在有关大规模恶意软件攻击的突发新闻中很常见，因为研究人员需要时间来筛选证据。我们鼓励读者在新的进展出现后回来查看。

这些指标可以帮助最终用户确定他们是否受到影响，但所需的技能对许多人来说可能遥不可及。

此类攻击暴露了SaaS供应链中第三方JavaScript代码库的信任边界缺陷，即使代码拥有合法数字签名也无法免疫恶意劫持。对于企业而言，单纯依赖CDN分发信任已失效，必须强制实施严格的子资源完整性（SRI）校验及动态实时内容安全策略（CSP）。
