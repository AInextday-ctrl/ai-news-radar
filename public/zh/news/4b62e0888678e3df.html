Anthropic发布Claude Artifacts应用安装功能

✍️ 记者 / 供稿: MacStories

Anthropic在Claude桌面端推出Artifacts“安装为应用”功能，支持将网页端生成内容转化为独立的本地桌面应用

⚡ 核心要点提炼与关键事实

  • 【核心事件】Anthropic（人工智能研究公司）在Claude桌面客户端（Mac/Windows）：支持将Artifacts内容通过Electron技术转化为独立桌面应用，同步调用Claude模型与连接器能力
  • 【起因与机理】旨在降低代码生成内容的交付门槛，打破传统应用分发范式，增强用户对生成式AI工具的使用粘性
  • 【核心事实细节】Artifacts支持转化为独立桌面应用（含图标与独立窗口）。
  • 【各方立场与态度】预示AI厂商向软件分发平台转型的底层技术野心。

MacStories 权威实录

昨天，Anthropic 宣布了一项针对工件的重要新功能，现已推出适用于 Mac 和 Windows 的测试版：用户能够将工件转变为可以安装在计算机上的“应用程序”。来自该公司的博客：

从今天开始，您可以使用 Claude 工件来创建、运行和共享桌面应用程序。 “安装为应用程序”功能正在 Mac 和 Windows 版 Claude 中推出测试版。

当工件作为 Mac 或 Windows 应用程序安装时，它会获得自己的图标并在自己的窗口中打开，而不是在 Claude 内打开。您可以与其他人共享它，并且它需要您的许可才能与您的计算机交互。您选择允许的数量。

每个应用程序都可以使用 Claude 和您的连接器，并且当编辑底层工件时它会自动更新。这简化了知识工作者和开发人员构建和维护应用程序的过程。应用程序向 Claude 发出的请求计入您计划的使用限制。

如果您是 AppStories 的听众，您就会知道，我长期以来一直认为，一个大型实验室找出如何将其模型的前沿编码能力转变为颠覆 App Store 的手段只是时间问题。这一举措感觉像是 Anthropic 朝这个方向迈出的第一步。

在讨论技术细节之前，让我先说一下：如果我是苹果公司，我会非常担心 Anthropic 现在正在为用户提供一个包装精美的系统，让用户可以制作他们想要的任何应用程序，并将苹果的生态系统变成克劳德的计算机上的工具和模组生态系统。

现在，Anthropic 实现这一目标的方式还存在争议，但我认为该系统是基于一些巧妙的工程和精明的锁定策略。首先，为了使这些应用程序正常工作，您需要安装主克劳德应用程序并使用您的帐户登录。这些应用程序需要运行主 Claude 进程，因为它们执行的每个操作实际上都是由 Claude 应用程序在幕后处理的，包括“完全磁盘访问”等权限。所有使用 Claude 制作的应用程序（无论是您制作的应用程序，还是其他人与您共享的应用程序）都安装在 ~/Applications/Claude Apps 中，因此它们由 Spotlight 索引，并且可以固定到 macOS Dock。事实上，当您第一次在 Claude 对话（可以是常规的 Claude 会话 - 您不需要为此使用 Claude Code）中创建应用程序时，有一个可爱的动画和安装流程，可将应用程序直接放入您的 Dock 中。这与“快捷方式”应用程序向 Mac 的 Dock 添加单独的快捷方式的方式并没有太大不同。

至关重要的是，这些不是使用 Swift 或 SwiftUI 创建的本机应用程序：它们是 HTML 应用程序，包装在 Electron shim 中，完全由 Claude 的 Electron Chromium 流程管理。这有点让人想起 Raycast 的 Glaze 产品，该产品使用 Vite/React Web 应用程序，在 Apple 的 WKWebView 内呈现，并封装在自定义 Swift shell 中。 （Glaze 还添加了将本机 Swift 模块集成到其应用程序中的功能；我希望 Anthropic 也能添加此功能。）

此举标志着模型厂商正试图通过OS层面的渗透，将AI模型从单一聊天界面转化为替代轻量级软件分发的底层平台。通过将本地应用生命周期与Claude账号权限绑定，Anthropic正在建立一套基于生成式UI的生态闭环，实质上挑战了现有应用商店对软件交互与分发的垄断权。
