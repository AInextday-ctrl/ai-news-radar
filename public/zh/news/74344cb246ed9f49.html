OpenAI发布医疗领域计算机使用代理

✍️ 记者 / 供稿: OpenAI 官方动态

OpenAI推出针对医疗工作流的AI代理，可跨系统执行审批与文档管理，并满足HIPAA合规要求

⚡ 核心要点提炼与关键事实

  • 【核心事件】OpenAI：推出具备跨应用操作能力的计算机使用代理，支持医疗机构实现病历录入、保险审批的自动化
  • 【起因与机理】医疗行业现有IT系统高度碎片化，亟需AI解决跨平台的人工操作痛点
  • 【核心事实细节】实现跨医疗系统软件的人工化自动交互。
  • 【各方立场与态度】通过API直接对接医疗机构现有工作流。

🤖 雷达专属 AI 研判与技术透视

此类Agent代表了从‘内容生成’到‘任务代理’的技术范式转变。通过直接操作图形界面，OpenAI实质上绕过了医疗行业遗留系统API开放缓慢的顽疾，一旦在金融、物流等高监管行业推广，将彻底改变B2B软件的集成逻辑与市场格局。

OpenAI 官方动态 权威实录

医疗保健是分散的，团队通常需要在患者获得护理之前在系统之间手动移动信息。例如，当临床医生推荐 MRI 时，保险公司所需的信息可能位于患者的医疗记录中，但团队成员仍然需要检索该信息并将其输入到单独的门户中以完成授权请求。

计算机使用代理通过单击、键入和在应用程序之间移动来执行多步骤工作流程。在医疗保健领域，这使得人工智能能够帮助完成已经使用的软件团队中的重复工作流程。

今天，我们将分享衡量临床和管理工作流程中模型性能、安全性和成本的新结果。我们还分享了与 Abridge、Ambience、Cigna Healthcare 和 CVS Health 等领先医疗保健组织合作的方式，以在授权请求、转诊、出院计划和就诊之间的外展方面推进和应用计算机使用。

医疗保健团队、开发人员和个人临床医生现在可以通过 OpenAI API、ChatGPT for Healthcare 和 ChatGPT for Clinicians 访问这些功能。组织可以支持符合 HIPAA 的工作流程、配置审批和代理访问并记录安全部署的审核日志。

为了展示计算机使用代理如何帮助临床医生和授权专家处理同一 MRI 请求，我们使用合成患者数据构建了一个演示。一名患者向临床医生发送有关腰痛的信息。计算机使用代理会审查患者的就诊记录、物理治疗记录和电子病历中先前的成像。它起草一份 MRI 命令、一份就诊记录以及给患者的答复，供临床医生审查。然后，代理人使用相同的记录在保险公司的门户中准备事先授权请求，以供授权专家审核。

我们针对临床医生在 EHR 收件箱中处理的任务评估了 GPT-6 Astra。这些任务由医生输入决定，要求 Astra 执行多步骤工作流程，旨在测试纵向患者背景的临床推理和复杂界面的导航。评审员检查了模型的行为以及它产生的注释、命令和患者消息，评估这项工作在任务背景下是否有帮助和临床安全。

通过评估模型工作中的不准确、遗漏或行为是否可能导致患者伤害来评估临床安全性。总体而言，325 项审核任务中 99% 被评为安全。医生按照五分制对有用性进行评分，在 646 项评估中，93% 选择“非常有帮助”或“非常有帮助”。

我们还评估了计算机使用代理执行行政任务的能力，例如事先授权、上诉和医疗设备订单。在 HealthAdminBench（在新窗口中打开）（斯坦福大学研究人员衡量常见管理工作流程性能的独立基准）上，GPT-6 Astra 获得了 94.3% 的可用评分，而 GPT-6 Luna 获得了 91.8%，尽管每项任务的成本降低了 98%，为 8.5 美分。两种模型均以最大推理努力进行评估。这些结果表明，在为大容量管理工作流程提供功能强大、价格实惠的代理方面取得了进展。

我们的合作伙伴构建了用于数百个卫生系统的软件，协调全球会员的护理，并为数亿患者提供护理。以下示例展示了组织如何开发、试点和部署计算机应用程序以节省时间、解决关键问题和改善患者护理。

CVS Health 正在使用 OpenAI 的计算机使用功能来自动化跨临床系统的重复性工作，包括发送文档、处理转诊和支持专家咨询。代理导航现有应用程序以完成 API 不完全支持的步骤。

在一个生产工作流程中，一名代理在周末清理了长达数月的文档发送积压工作。另一个人每天处理数以万计的咨询的系统步骤，帮助团队成员专注于需要他们专业知识的工作。 CVS Health 使用验证检查和人工监督，并通过屏幕截图和操作记录来验证操作和应用程序状态。 CVS Health 正在开源其 Agent Kit（在新窗口中打开），该工具包使用 OpenAI 的 Agents SDK 构建，将该方法打包为可重复的流程以供更广泛的使用。

数据保留在 CVS Health 企业控制的基础设施内，由其企业 AI 治理团队管理并制定负责任的 AI 政策。生产数据不用于训练基础模型。

Abridge 正在开发计算机使用代理，以帮助临床医生跨日常使用的用例和应用程序（包括那些没有 API 的用例和应用程序）执行护理计划。他们计划的住院患者用例建立在临床对话的基础上，添加 EHR 信息以及护士和临床医生的背景信息，以确定需要注意的事项并协调后续步骤。

例如，临床医生可以要求 Abridge 助理帮助解决患者的出院障碍。代理可以利用计算机交互以及电话和消息，同时进行药物获取和家庭健康协调。临床医生始终关注患者并做出需要临床判断的决定。
