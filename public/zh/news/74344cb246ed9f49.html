OpenAI发布医疗领域计算机使用代理

✍️ 记者 / 供稿: OpenAI

OpenAI推出针对医疗工作流的AI代理，可跨系统执行审批与文档管理，并满足HIPAA合规要求

⚡ 核心要点提炼与关键事实

  • 【核心事件】OpenAI：推出具备跨应用操作能力的计算机使用代理，支持医疗机构实现病历录入、保险审批的自动化
  • 【起因与机理】医疗行业现有IT系统高度碎片化，亟需AI解决跨平台的人工操作痛点
  • 【核心事实细节】实现跨医疗系统软件的人工化自动交互。
  • 【各方立场与态度】通过API直接对接医疗机构现有工作流。

OpenAI 官方动态 权威实录

医疗保健是分散的，团队通常需要在患者获得护理之前在系统之间手动移动信息。例如，当临床医生推荐 MRI 时，保险公司所需的信息可能位于患者的医疗记录中，但团队成员仍然需要检索该信息并将其输入到单独的门户中以完成授权请求。

计算机使用代理通过单击、键入和在应用程序之间移动来执行多步骤工作流程。在医疗保健领域，这使得人工智能能够帮助完成已经使用的软件团队中的重复工作流程。

今天，我们将分享衡量临床和管理工作流程中模型性能、安全性和成本的新结果。我们还分享了与 Abridge、Ambience、Cigna Healthcare 和 CVS Health 等领先医疗保健组织合作的方式，以在授权请求、转诊、出院计划和就诊之间的外展方面推进和应用计算机使用。

医疗保健团队、开发人员和个人临床医生现在可以通过 OpenAI API、ChatGPT for Healthcare 和 ChatGPT for Clinicians 访问这些功能。组织可以支持符合 HIPAA 的工作流程、配置审批和代理访问并记录审核日志以实现安全部署。

从患者的消息到 MRI 授权请求

为了展示计算机使用代理如何帮助临床医生和授权专家处理同一 MRI 请求，我们使用合成患者数据构建了一个演示。一名患者向临床医生发送有关腰痛的信息。计算机使用代理会在 EHR 中查看患者的就诊记录、物理治疗记录和先前的成像。它起草一份 MRI 命令、一份就诊记录以及给患者的答复，供临床医生审查。然后，代理人使用相同的记录在保险公司的门户中准备事先授权请求，以供授权专家审核。

评估有用性、安全性和成本

我们针对临床医生在 EHR 收件箱中处理的任务评估了 GPT-6 Astra。这些任务由医生输入决定，要求 Astra 执行多步骤工作流程，旨在测试纵向患者背景的临床推理和复杂界面的导航。评审员检查了模型的行为以及它产生的注释、命令和患者消息，评估这项工作在任务背景下是否有帮助和临床安全。

通过评估模型工作中的不准确、遗漏或行为是否可能导致患者伤害来评估临床安全性。总体而言，325 项审核任务中 99% 被评为安全。医生按照五分制对有用性进行评分，在 646 项评估中，93% 选择“非常有帮助”或“非常有帮助”。

EHR 收件箱工作示例

我们还评估了计算机使用代理执行行政任务的能力，例如事先授权、上诉和医疗设备订单。在 HealthAdminBench（斯坦福大学研究人员衡量常见管理工作流程性能的独立基准）上，GPT-6 Astra 获得了 94.3% 的可用评分分数，而 GPT-6 Luna 获得了 91.8%，尽管每项任务的成本降低了 98%，为 8.5 美分。两种模型均以最大推理努力进行评估。这些结果表明，在为大容量管理工作流程提供功能强大、价格实惠的代理方面取得了进展。

与医疗保健组织一起开发计算机使用

我们的合作伙伴构建了用于数百个卫生系统的软件，协调全球会员的护理，并为数亿患者提供护理。以下示例展示了组织如何开发、试点和部署计算机应用程序以节省时间、解决关键问题和改善患者护理。

CVS Health：完成跨临床系统的行政工作

CVS Health 正在使用 OpenAI 的计算机使用功能来自动化跨临床系统的重复性工作，包括发送文档、处理转诊和支持专家咨询。代理导航现有应用程序以完成 API 不完全支持的步骤。

在一个生产工作流程中，一名代理在周末清理了长达数月的文档发送积压工作。另一个人每天处理数以万计的咨询的系统步骤，帮助团队成员专注于需要他们专业知识的工作。 CVS Health 使用验证检查和人工监督，并通过屏幕截图和操作记录来验证操作和应用程序状态。 CVS Health 正在开源其 Agent Kit，该工具包是使用 OpenAI 的 Agents SDK 构建的，该工具包将此方法打包为可重复的流程以供更广泛的使用。

数据保留在 CVS Health 企业控制的基础设施内，由其企业 AI 治理团队管理并制定负责任的 AI 政策。生产数据不用于训练基础模型。

Abridge：每个护理时刻的跨系统协调

Abridge 正在开发计算机使用代理，以帮助临床医生跨日常使用的用例和应用程序（包括那些没有 API 的用例和应用程序）执行护理计划。他们计划的住院患者用例建立在临床对话的基础上，添加 EHR 信息以及护士和临床医生的背景信息，以确定需要注意的事项并协调后续步骤。

例如，临床医生可以要求 Abridge 助理帮助解决患者的出院障碍。代理可以利用计算机交互以及电话和消息，同时进行药物获取和家庭健康协调。临床医生始终关注患者并做出需要临床判断的决定。

Cigna：让护理经理为会员外展做好准备

作为 Cigna Group 与 OpenAI 更广泛合作的一部分，Cigna Healthcare 正在使用 OpenAI 的前沿模型以及自己的临床专业知识来汇集跨系统的相关信息，并为护理团队提供有关每个成员的需求和经验的更完整的背景信息。这可以包括有关福利和承保范围、提供者、预约和之前互动的信息，帮助护理团队更好地支持成员围绕其治疗提供者制定的护理计划。

此前，Cigna Healthcare 案例经理必须浏览 10 多个独立的临床和管理系统才能收集此背景信息。现在，计算机的使用可以帮助导航这些系统，并在几秒钟内将相关信息整合在一起，从而减少搜索信息所花费的时间，最终使案例经理有更多时间来支持成员。

氛围：使计算机在医疗保健中的使用变得可控

计算机的使用让代理可以完成 EHR 和付款人门户中 API 无法到达的任务。在医疗保健领域，只有每项操作都受到控制且可审计时，该功能才可用。 Ambience 建立了额外的控制措施来支持这种监督。

在此演示中，Ambience 使用患者病历中的证据在保险公司的网站上准备预先授权请求。当记录不明确时，代理人停下来询问临床医生，然后等待批准后再提交。健康系统设置代理可以采取哪些操作，可以随时暂停它，并获取分步日志以供审核。

医疗保健初创公司正在帮助将计算机使用的进步转化为支持护理团队的新方式。这五家公司将人工智能代理与医疗保健专业知识相结合，帮助团队导航系统、协调后续步骤并推动护理向前发展。

患者数据安全和代理控制

医疗保健领域的计算机使用代理需要评估临床安全性、保护患者信息，并对代理在没有人工审查的情况下可以执行的操作设置明确的限制。

ChatGPT for Healthcare 提供基于角色的访问控制和审核日志以支持监督。组织可以在其工作流程中构建额外的审核和批准步骤，并配置代理用于限制对每项任务所需的记录和操作的访问的应用程序和环境。组织数据不用于训练 OpenAI 基础模型。

为了支持涉及受保护健康信息的符合 HIPAA 的工作流程，组织必须使用其与 OpenAI 的业务伙伴协议涵盖的合格服务以及所需的安全和保留设置。

开始使用计算机使用代理

目前，用于医疗保健的计算机使用代理可在 ChatGPT for Healthcare、ChatGPT for Clinicians 和 OpenAI API 中使用。以下是医疗保健组织、临床医生和开发人员可以如何开始使用。

医疗保健组织：联系我们的销售团队，讨论在您的临床和管理工作流程中使用人工智能。现有客户可以要求其工作区管理员启用 ChatGPT Work 和 Codex 中的计算机使用。

开发人员：使用 OpenAI API 构建医疗保健应用程序，并探索我们的计算机使用指南来构建跨现有软件工作的代理。

我们希望这些进步使医疗团队能够花更少的时间通过系统传输信息，而将更多的时间花在照顾患者上。
